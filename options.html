⚙ Kanban Flow — Configuration

Connexion JIRA Cloud, équipes et définitions des indicateurs.

1. Connexion JIRA Cloud

Format : https://<votre-domaine>.atlassian.net
Créez-en un sur id.atlassian.com › API tokens. Stocké localement dans le navigateur.

2. Réglages des indicateurs

Première semaine de référence. On affiche la semaine en cours + jusqu'à 3 semaines complètes précédentes, sans jamais remonter avant cette date. Vide = 3 semaines précédentes par défaut.
Variation en-deçà de laquelle la tendance est « stable ».
Laissez vide pour une détection automatique (« Story Points » / « Story point estimate »). À renseigner si votre site JIRA utilise un nom de champ inhabituel.

Créneaux de comptage (mode Build)

Réglage global : appliqué à toutes les équipes en mode Build. Les bornes de fin sont exclues (« vendredi fin de journée » = samedi 00:00).

Tickets présents sur le board pendant ce créneau.

3. Équipes / Projets

Renseignez pour chaque équipe la clé de projet JIRA et les statuts exacts de vos workflows. Les statuts sont séparés par des virgules et doivent correspondre exactement (casse ignorée) aux noms dans JIRA.

4. Sauvegarde de la configuration

Exportez votre configuration dans un fichier avant toute mise à jour de l'extension, puis réimportez-la après : rien à ressaisir. Le fichier peut aussi être partagé à un collègue pour qu'il démarre avec les mêmes équipes.

Décoché par défaut : le jeton est un secret équivalent à un mot de passe. Sans lui, tout le reste est restauré et il suffit de recoller le jeton. À l'import, un fichier sans jeton ne supprime jamais celui déjà enregistré.
